# Playtime Pact — 함께 정하고, 스스로 지키는 게임 시간

**부모와 자녀가 약속한 게임 시간을 눈에 보이게 만들고, 스스로 게임을 마무리하도록 돕는 Windows 앱입니다.**

Roblox와 Minecraft를 실행하면 타이머가 자동으로 시작됩니다. 남은 시간과 종료 전 경고를 보여 주고, 시간이 끝나면 감지한 게임을 종료합니다. 부모는 PIN으로 사용 규칙과 추가 시간을 관리합니다.

현재 Windows 코드 버전은 **0.60.8**입니다. Android 부모 앱과 원격 승인 서버 코드도 있지만, Windows 사용에 모바일 연결은 필수가 아니며 모바일 출시 완료를 의미하지 않습니다.

## 왜 만들었나요?

“조금만 더 할게요”와 “이제 그만해”를 매일 반복하는 대신, 시작 전에 함께 정한 규칙을 앱이 일관되게 안내하도록 만들었습니다. **Pact**는 서로 진지하게 지키기로 한 약속을 뜻합니다. 게임을 무조건 막는 것이 아니라, 남은 시간을 알고 스스로 저장하고 마무리하는 습관이 목표입니다.

## 지원 게임

| 게임 | 관리 대상 | 확인 범위 |
| --- | --- | --- |
| **Roblox** | Windows Roblox Player 게임 프로세스 | 실행 파일 분류 회귀검사 완료. 최신 실게임 전체 흐름은 미검증 |
| **Minecraft: Java Edition** | Minecraft로 식별되는 Java 게임 프로세스 | 실제 감지·타이머·종료 시험 수행 |
| **Minecraft: Bedrock Edition** | Windows용 Minecraft 게임 프로세스 | 감지 로직 포함. 별도 Bedrock 실게임 전체 흐름은 미검증 |
| **Lunar Client** | Lunar에서 실행한 Minecraft Java 세션 | 실제 세션 및 사용량 소진 후 재실행 종료 시험 수행 |

Minecraft Launcher와 Lunar Client의 **런처 창만 열어 두는 것은 게임 플레이로 계산하지 않습니다.** Roblox Studio·설치 프로그램·충돌 보고 프로그램도 Roblox 게임으로 취급하지 않습니다. 일반 Java 프로그램을 모두 종료하는 방식이 아니라 Minecraft 관련 정보를 확인합니다.

다른 Minecraft 클라이언트의 식별 규칙도 일부 포함되어 있지만, 모든 런처·모드·업데이트 조합을 검증한 것은 아닙니다. 지원 게임은 하나의 사용 시간·횟수 정책을 공유합니다.

## 어떻게 동작하나요?

1. **부모가 규칙을 정합니다.** 평일·주말의 시간과 횟수, 게임을 허용할 시간대를 설정합니다.
2. **자녀가 게임을 직접 실행합니다.** 실제 지원 게임을 감지하면 허용 조건을 확인하고 타이머가 시작됩니다. 앱이 게임을 대신 실행하지는 않습니다.
3. **남은 시간을 안내합니다.** 작은 타이머와 단계별 경고, 마지막 카운트다운으로 마무리할 시간을 알려 줍니다.
4. **끝난 시간을 적용합니다.** 게임에 정상 종료를 먼저 요청하고 유예 후에도 남으면 강제 종료를 시도합니다. PID와 시작 시각을 재확인해 다른 프로세스의 오종료를 줄입니다.
5. **필요하면 부모가 조정합니다.** 부모 PIN으로 추가 시간·차감·중지·설정 변경을 관리합니다.

게임을 모두 닫으면 잔여 시간을 보존하고, 다시 실행하면 남은 시간부터 이어 갑니다. 허용 시간 밖이거나 사용량을 소진한 경우에는 안내 후 게임 실행을 제한합니다. 하루 사용 완료 화면에는 큰 중앙 카드와 작은 **추가 요청** 버튼을 표시합니다.

> 자동 종료는 월드 저장을 보장하지 않습니다. 경고가 나오면 직접 저장하고 종료해 주세요. 강제 종료가 필요한 경우 저장하지 않은 진행 상황이 손실될 수 있습니다. 정상 종료 유예와 시작 중인 게임의 창 생성 대기가 있어 시간 만료 즉시 프로세스가 사라지는 것은 아닙니다.

## Windows에 설치하기

대상은 **Windows x64**이며, 현재 실제 검증 환경은 Windows 11입니다.

1. 제공받은 `Playtime Pact Setup 0.60.8.exe`를 사용할 PC로 복사합니다. 설치 파일 하나면 되며 소스나 `win-unpacked` 폴더는 필요하지 않습니다.
2. 게임을 종료한 뒤 설치 파일을 실행하고 Windows 관리자 승인을 진행합니다. 보호 서비스와 자동 실행을 등록합니다.
3. 신규 설치의 초기 부모 PIN은 `0000`입니다. **관리자 화면의 부모 PIN 변경에서 즉시 바꿔 주세요.** 기존 설치를 업데이트할 때는 기존 PIN을 사용합니다.
4. 사용 규칙을 확인합니다. 모바일을 쓰지 않으면 모바일 승인 옵션을 끈 상태로 사용합니다.
5. 첫 사용 시 부모 입회하에 짧은 시간으로 게임 감지·경고·종료를 확인합니다.

현재 0.60.8 설치 후보는 **코드 서명되지 않은 파일**입니다. Windows 경고가 나타날 수 있습니다. 출처와 해시를 확인하고, 조직 정책이나 보안 기능을 끄면서 설치하지 마세요. 자세한 내용은 [Windows 설치 안내](WINDOWS_INSTALL.md)를 참고하세요.

[GitHub Releases](https://github.com/toughCSB/Playtime-pact/releases)의 파일은 버전을 먼저 확인하세요. **소스 업데이트와 설치 파일의 Release 게시는 별개이며, 이 README는 0.60.8 설치 파일이 공개 게시되었다는 뜻이 아닙니다.**

## 부모 보호 기능과 한계

- 설정 변경·시간 조정·앱 완전 종료·제거에 부모 PIN 확인을 사용합니다.
- 일반적인 창 닫기는 종료 대신 트레이 숨김으로 처리합니다.
- Windows 보호 서비스와 watchdog으로 사용량 관리와 자동 실행을 지원합니다.
- 자녀에게는 표준 Windows 계정을 사용하고 관리자 계정은 부모가 관리하는 구성을 권장합니다.
- 관리자/SYSTEM 권한 사용자의 모든 우회를 막는 보안 제품은 아닙니다. Windows 관리자 승인과 부모 PIN은 서로 다른 인증입니다.
- 모바일 원격 승인을 켜려면 Android 앱 및 서버의 별도 설정과 검증이 필요합니다. 로컬 PIN 방식과 혼동하지 마세요.

## 0.60.8에서 달라진 점

- Roblox 중심 도구에서 Minecraft Java/Bedrock와 Lunar의 Minecraft 세션까지 관리하는 Playtime Pact로 정리했습니다.
- Windows 프로세스 조회를 비동기로 처리하고 독립적인 시간 제한을 두어 조회 지연이 타이머 화면을 멈추지 않도록 보강했습니다.
- 게임 종료 전 프로세스 신원 재확인, 정상 종료 요청·유예·강제 종료 및 결과 확인을 보강했습니다.
- 보호된 사용량 저장과 재실행·시간 조정의 경쟁 조건을 보강했습니다.
- 설치 파일 잠금 시 복구 흐름을 개선했습니다. 모든 PC의 업그레이드·복구 경로가 검증됐다는 의미는 아닙니다.
- 부모 제어의 중복 입력 방지, 오류 안내, 작은 화면 대응 및 하루 사용 완료 안내를 개선했습니다.

## 검증 상태

2026-09-09의 현재 Windows 후보 기준:

- `npm test`: **423개 통과, 7개 건너뜀** — Vitest 296개 + 직렬 Node 테스트 127개 통과.
- `npm run typecheck` 및 Windows NSIS 패키징 통과.
- 사용 완료 안내 화면은 5개 창 크기에서 레이아웃 검사 통과.
- Minecraft/Lunar 실제 실행 관련 시험을 수행했습니다. 모든 경고 시점·저장 무결성·게임 조합을 확인한 것은 아닙니다.
- **다른 PC의 신규 설치, 최신 설치본의 전체 업그레이드/잠금 복구, Roblox·Bedrock 실게임 전체 흐름은 미검증입니다.** 코드 서명·모바일 및 macOS 출시 검증도 완료하지 않았습니다.

## 개발 및 빌드

루트 패키지 관리자는 npm입니다. Node.js는 설치된 Vite의 요구 범위인 **20.19+ 또는 22.12+**를 사용합니다.

```powershell
npm ci
npm run typecheck
npm test
npm run build
npm run dev
```

Windows 설치 파일:

```powershell
# 로컬 검증용 미서명 설치본: dist/에 생성
npm run package:win:unsigned

# 인증서 또는 Azure Trusted Signing 설정이 필요한 서명 빌드
npm run package:win
```

이전 패키지 폴더의 `app.asar`가 잠겨 있으면 패키징이 실패할 수 있습니다. 기존 파일을 사용하는 앱을 확인하거나 새 출력 폴더를 사용하세요. 테스트 패키지·개인 설정·인증서·비밀값은 커밋하지 않습니다.

## 저장소 구성

| 위치 | 역할 |
| --- | --- |
| `src/main/` | Electron 메인, 게임 감지·타이머·보호 서비스 |
| `src/preload/`, `src/shared/` | 타입이 있는 화면 통신과 공통 규칙 |
| `src/renderer/` | React 타이머·설정·부모 제어 화면 |
| `build/`, `resources/`, `scripts/` | Windows 설치·실행·서명·검증 지원 |
| `tests/`, `proofs/` | 자동 테스트와 프로토콜 검증 자료 |
| `android-parent/` | 별도 Android 부모 앱 |
| `remote-backend/`, `ops/` | Cloudflare Worker/D1 원격 승인 및 운영 자료 |

현재 Windows 상태는 이 문서와 [Windows 설치 안내](WINDOWS_INSTALL.md)를 기준으로 보세요. [변경 이력](CHANGELOG.md)과 [이전 프로젝트 계획](PROJECT_STATUS.md)은 해당 기록의 기준일과 함께 읽어 주세요.
